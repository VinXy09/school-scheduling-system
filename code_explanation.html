Code & Database Connection

1. Establishing the Connection

In backend/server.js, the server establishes a persistent link to the MySQL database.

const db = mysql.createConnection({
    host: process.env.DB_HOST,
    user: process.env.DB_USER,
    password: process.env.DB_PASSWORD,
    database: process.env.DB_NAME,
    multipleStatements: true 
});

db.connect(err => {
    if (err) console.error('❌ Connection Failed');
    console.log('✅ Connected to ID: ' + process.env.DB_NAME);
});
DATABASE CONFIGURATION
The mysql2 library is used to create a "bridge" between the server and the data storage.

2. The Scheduling Table Structure

This is how the room_schedules table is structured to connect everything.

CREATE TABLE IF NOT EXISTS room_schedules (
    id INT AUTO_INCREMENT PRIMARY KEY,
    room_id INT,           // Reference to Rooms
    course_id INT,         // Reference to Subjects
    instructor_id INT,     // Reference to Faculty
    day_of_week VARCHAR(50),
    start_time TIME,
    end_time TIME
);
FOREIGN KEY POINTERS
Each schedule record "points" to three other pieces of information: a Room, a Subject, and an Instructor.

3. Saving Data (The Connection in Action)

When you click "Save Schedule" in the UI, this code in server.js triggers the database save.

app.post('/api/schedules', (req, res) => {
    const { room_id, course_id, instructor_id, ...data } = req.body;
    
    const sql = "INSERT INTO room_schedules SET ?";
    
    db.query(sql, req.body, (err, result) => {
        if (err) return res.status(500).json(err);
        res.json({ success: true, id: result.insertId });
    });
});
INSERT QUERY
The server takes your form data and Injects it into the MySQL table using a SQL query.
